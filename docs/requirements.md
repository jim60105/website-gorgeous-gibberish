# 聊天機器人網站「絢」需求文檔

## 專案概述

「絢」是一個聊天機器人網站，用戶可以輸入簡短的詞語或短句，AI 會圍繞該主題生成冗長且絢爛的回應。網站採用黑暗簡潔的視覺設計，與 AI 絢麗的文字回應形成強烈反差。

- **網站名稱**: 絢 (hsüan4)
- **網域**: 絢.tw
- **核心理念**: 視覺簡約與文字絢爛的反差美學

## 功能特性 (Features)

### Feature 1: 用戶輸入管理
**作為** 網站訪客  
**我想要** 能夠輸入簡短的詞語或問題  
**以便** 獲得 AI 的絢爛回應

#### Scenario 1.1: 輸入短語或問題
**Given** 我在網站首頁  
**When** 我在輸入框中輸入文字  
**Then** 系統應該接受我的輸入  
**And** 輸入字數不應超過 20 字

#### Scenario 1.2: 即時字數計數
**Given** 我正在輸入框中打字  
**When** 我輸入或刪除文字  
**Then** 系統應該即時顯示當前字數和限制 (如 "12/20")  
**And** 接近限制時應該改變顯示顏色提醒  
**And** 超過限制時應該阻止進一步輸入

#### Scenario 1.3: 對話次數視覺化
**Given** 我已經在同一個對話中發送了訊息  
**When** 我查看對話狀態  
**Then** 我應該能看到 5 個點狀指示器顯示對話進度  
**And** 已使用的對話次數顯示為實心圓 (●)  
**And** 剩餘的對話次數顯示為空心圓 (○)  
**And** 當達到 5 次限制時，系統應該提供重新開始的選項

#### Scenario 1.4: 預填隨機短語
**Given** 我是首次訪問網站的用戶  
**When** 頁面載入完成  
**Then** 輸入框應該預填一個隨機短語  
**And** 我可以直接發送或修改後發送

### Feature 2: AI 回應生成
**作為** 用戶  
**我想要** 收到基於我輸入主題的詳細回應  
**以便** 體驗 AI 的絢爛文字表達

#### Scenario 2.1: 生成長篇回應
**Given** 我已經提交了一個短語  
**When** AI 開始處理我的輸入  
**Then** AI 應該圍繞我的主題生成非常長的詳細回應  
**And** 回應內容應該豐富且具有絢爛的文字風格

#### Scenario 2.2: 流式輸出顯示
**Given** AI 正在生成回應  
**When** 回應開始輸出  
**Then** 文字應該以流式方式逐字顯示  
**And** 輸出過程應該包含打字機效果動畫

#### Scenario 2.3: 主題相關性
**Given** 我輸入了特定主題（如"晚餐吃什麼"）  
**When** AI 生成回應  
**Then** 回應內容應該與我的輸入主題相關  
**And** 用戶輸入應該作為回應的核心主題

### Feature 3: 視覺設計與用戶體驗
**作為** 用戶  
**我想要** 享受優雅的視覺體驗和流暢的動畫  
**以便** 獲得愉悅的使用感受

#### Scenario 3.1: 首頁佈局
**Given** 我首次訪問網站  
**When** 頁面載入  
**Then** 我應該看到黑暗主題的簡潔設計  
**And** 輸入框應該位於頁面正中央  
**And** 整體設計應該簡單清爽

#### Scenario 3.2: 版面轉換動畫
**Given** 我在首頁輸入框中提交了內容  
**When** AI 開始回應  
**Then** 版面應該通過流暢的 CSS 動畫轉換為對話模式  
**And** 轉換過程應該自然不突兀

#### Scenario 3.3: 文字層次設計
**Given** AI 正在顯示回應  
**When** 我查看對話界面  
**Then** AI 回應文字應該較大且突出顯示  
**And** 我的輸入應該以較小文字作為主題提示顯示  
**And** 形成清晰的視覺層次

#### Scenario 3.4: 響應式設計
**Given** 我使用不同設備訪問網站  
**When** 我在桌面或移動設備上瀏覽  
**Then** 網站應該在所有設備上正常顯示  
**And** 動畫效果應該在所有設備上流暢運行

### Feature 4: 技術實現與性能
**作為** 開發者和用戶  
**我想要** 網站具有良好的性能和技術實現  
**以便** 確保穩定可靠的使用體驗

#### Scenario 4.1: 一頁式網站架構
**Given** 網站需要簡潔的用戶體驗  
**When** 用戶瀏覽網站  
**Then** 所有功能應該在單一頁面內完成  
**And** 不需要頁面跳轉或重新載入

#### Scenario 4.2: 技術棧實現
**Given** 網站需要輕量且高效的實現  
**When** 開發網站功能  
**Then** 應該使用 Tailwind CSS 作為主要樣式框架  
**And** 使用純 JavaScript 實現互動功能  
**And** 僅在 Tailwind 無法實現時使用獨立 CSS 文件

#### Scenario 4.3: 隨機短語系統
**Given** 需要為用戶提供輸入靈感  
**When** 頁面載入或用戶需要新的提示  
**Then** 系統應該從預設陣列中隨機選取短語  
**And** 短語應該多樣化且有趣

#### Scenario 4.4: OpenAI API 整合
**Given** 需要 AI 回應功能  
**When** 用戶提交輸入  
**Then** 系統應該使用 OpenAI JS SDK 調用 OpenAI Compatible API  
**And** 直接與 OpenAI 後端服務通信

## 驗收標準 (Acceptance Criteria)

### 性能標準
- **頁面載入時間**: < 2 秒
- **流式輸出延遲**: < 100ms
- **動畫幀率**: ≥ 60fps
- **API 回應時間**: < 3 秒開始流式輸出

### 可用性標準
- **響應式設計**: 支援桌面和移動設備
- **鍵盤支援**: Enter 鍵發送訊息
- **瀏覽器相容**: Chrome, Firefox, Safari, Edge 最新版本

### 功能標準
- **輸入限制**: 嚴格執行 20 字限制
- **對話限制**: 嚴格執行 5 次訊息限制
- **流式輸出**: 文字逐字顯示效果
- **動畫效果**: 流暢的版面轉換和打字機效果

## 技術約束與限制

### 必須遵循的技術規範
- **主要框架**: Tailwind CSS
- **腳本語言**: 純 JavaScript (無框架依賴)
- **樣式擴展**: 僅在 Tailwind 無法實現時使用 CSS
- **API 通信**: 使用 OpenAI JS SDK
- **架構模式**: 單頁應用 (SPA) 設計
- **後端服務**: 直接連接 OpenAI Compatible API

### 設計約束
- **視覺風格**: 黑暗主題，簡潔設計
- **色彩方案**: 以黑、白、灰為主調
- **字體層次**: AI 回應大字體，用戶輸入小字體
- **動畫原則**: 流暢自然，不過度炫技

## Definition of Done

一個功能被認為完成當：
- ✅ 所有相關的 Scenario 都通過測試
- ✅ 符合所有驗收標準
- ✅ 在所有支援的瀏覽器中正常運作
- ✅ 響應式設計在不同設備上測試通過
- ✅ 代碼通過 code review
